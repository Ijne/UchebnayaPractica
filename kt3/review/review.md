# Рецензирование исходного кода КТ3

## Общие сведения

- Автор: Чудаев Иван Сергеевич, ИКБО-10-24.
- Проверяемая версия: `src/python` и `src/java` из комплекта КТ3.
- Дата рецензирования: 17.11.2026.

## Критерии рецензирования

- совпадение результата Python и Java на `example_input.json`;
- явная связь партии с назначенной спецификацией;
- наличие `batch_id` и времени у каждого измерения;
- включение конфликтов в электронный протокол;
- инкапсуляция полей Java-классов;
- применение наследования, интерфейса с двумя реализациями и коллекций `List`, `Map`, `Set`;
- обработка допустимого значения, выхода за диапазон и отсутствующего норматива;
- команды сборки и запуска из `README.md`.

## Результаты проверки

1. **Выбор версии спецификации.** Поле `Batch.specificationId` однозначно определяет спецификацию партии. Тестовый набор содержит две версии и подтверждает использование назначенной версии.
2. **Состав электронного протокола.** `BatchProtocol` содержит измерения, отклонения, конфликты спецификаций и итоговый статус партии.
3. **Правила валидации.** Интерфейс `ValidationRule` реализован классами `SpecificationPresenceRule` и `RangeValidationRule`. Новое правило можно добавить без изменения `QualityControlService`.
4. **Уникальность измерений.** Метод `assertUniqueMeasurementIds()` использует `Set` и прекращает обработку при повторе идентификатора.
5. **Иерархия проблем качества.** Абстрактный класс `QualityIssue` хранит общие поля `batchId` и `measurementId`; классы `Deviation` и `SpecificationConflict` определяют собственные данные и сериализацию.
6. **Обработка JSON.** Класс `SimpleJson` поддерживает входной и выходной формат учебной консольной системы. Для серверной версии возможно применение Jackson и JSON Schema.

## Итог рецензирования

- сущности модели представлены отдельными классами с закрытыми полями;
- алгоритмические оценки O(n+m) и O(n·m) сохранены;
- Python и Java используют один входной файл и возвращают семантически одинаковый JSON;
- проект не требует внешних библиотек и собирается JDK 11;
- тесты охватывают основной сценарий, выход за допустимый диапазон и отсутствие норматива.

Исходный код соответствует модели предметной области и требованиям КТ3. Обе реализации воспроизводят один результат на общем входном наборе. Структура Java проекта допускает расширение набора правил контроля без изменения основного сервиса.
